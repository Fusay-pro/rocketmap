## Problem Statement

RocketMap was built as an AI canvas for idea-stage startups. Structural flaw: startup analysis critiques fiction with fiction (fake TAM, fake projections). Founder + dad want to put real capital into a real venture but status quo is gut (dad) + ChatGPT (founder) — "both are just biases."

Real job is not "smarter BMC" or "Alibaba scrape moat first." Real job: **know what to test before investing big money** — a pre-investment business case where numbers are grounded (quotes, measurements) or explicitly untested with a named Ries-style experiment. AI is a chat editor on content, never the source of truth for load-bearing figures.

## Demand Evidence

- Behavioral demand today is the founder–investor pair itself: founder wants to launch; dad wants to invest but "don't know what will work."
- Status quo admission: dad = informal/gut; founder asks AI; both acknowledge bias. No third-party paying customer yet.
- Strongest pull quote: ground supply (Alibaba/yellowpages), demand data, and unit econs "**before investing lots of money**."
- Not market demand for SaaS yet. Dogfood proof = whether a grounded case changes dad's capital decision.

## Status Quo

- Dad: informal research / gut.
- Founder: ask AI.
- Competitor is not another canvas product — it is **confident fiction** that feels like diligence.
- Incumbent tools (landed-cost calculators, supplier intel platforms) exist but assume FOB or optimize discovery; they do not produce a family-capital go/no-go packet with Ries tags.

## Target User & Narrowest Wedge

- **User:** Founder + dad on the founder's next venture (not abstract "SME operators" yet).
- **Wedge (Approach A):** One **Investment Case / Dad Decision Memo** for an imported/resold physical product path (see Recommended Approach for full spec).
- **Out of v1:** BMC grid redesign, yellowpages/scrape/API directory, live tariff feeds, billing, chat-first UX, OCR auto-fill, auto-verdict without founder confirmation, generalized SME platform.

## Constraints

- **Canonical evidence rule:** Every load-bearing number is `Quoted` (document attached), `Measured` (experiment result logged), or `Untested` **with a required planned-test name** (and optional experiment link). AI never invents numeric values for the Case.
- Supply side prefers documents; demand side prefers Lean tests (same tag system).
- Alibaba scrape deferred; directory = phase 2.
- Stack: Next.js App Router, TypeScript, Radix/Tailwind, Appwrite TablesDB + storage.
- Existing AI economics views (`EconomicsView` / deep-dive unit econ) are **out of scope** for Investment Case math — Case computes from ledger only.
- No billing in v1.

## Recommended Approach

**Approach A**, with engineering locks below.

### Phase gates (build order)

1. **Gate 0 (assignment, no code):** Paper/Notion memo with 2 quotes + 1 demand test + kill criteria → 30 min with dad → write which fields he asked for.
2. **Gate 1:** Schema + Investment Case CRUD + manual ledger entry + attachments + computed scenarios + founder-selected verdict + PDF/print memo.
3. **Gate 2 (optional):** AI wording help + "missing test" checklist only (still no invented numbers). OCR deferred to v1.1.

### Architecture lock

- **Dedicated route:** `/investment-case` (list + New) → create → `/investment-case/[id]`. **Not** a BMC canvas type. No `slug` column in v1.
- `capitalAvailable`: display-only on memo in v1 (not in formulas).
- On save: if `killDemandMetric` set, upsert the single demand-test row's `threshold` from `killDemandThreshold` (case is source of truth).
- **Measured tag examples:** sellPrice Measured = price observed in logged test/sale; targetVolume Measured = units preordered/sold in test.
- New Appwrite tables (manual console create). Avoid BMC grid coupling for v1.
- Dad distribution v1: **PDF / print memo** for logged-in founder. No guest auth / magic link in v1.
- **No `case_ledger_fields` table in v1** — only cases, quotes, demand_tests.

### Tag semantics (sell price & volume)

- **Quoted** = attached external evidence (customer quote, competitor listing screenshot, signed LOI).
- **Measured** = result from a logged demand test / survey with `evidenceFileId` or noted sample.
- **Untested** = hypothesis; **`plannedTest` string required**.

### Validation tiers

| Action | Allowed |
|--------|---------|
| **Draft save** | Incomplete quotes OK; tags optional; Untested without plannedTest OK |
| **Publish** | Primary quote complete (FOB+freight+duty+attachment); sellPrice + targetVolume tagged; if tag Quoted → require `sellPriceSourceNote` or attachment file ref on case (`sellPriceEvidenceFileId` / `targetVolumeEvidenceFileId` optional fields); if Measured → require demand test `evidenceFileId` or note linking measured observation; every Untested has plannedTest; if `killDemandMetric` set, exactly one demand test with matching metricName and `threshold === killDemandThreshold` (API syncs threshold from case on save); founder `verdict` ≠ unset |

### Load-bearing fields (publish)

- Primary quote: fob, freight, duty (+ attachment)
- `sellPricePerUnit` (+ tag / plannedTest)
- `targetVolume` (+ tag / plannedTest)
- Demand `result` only if `killDemandMetric` non-empty and status=done (else demand incompleteness → recommendation `test_again`, not a publish block unless you set a house rule later)

### Unit-econ formulas (v1)

All money in case `currency`. Per-unit landed (primary quote):

```
freightPerUnit = freightMode==total ? freightValue / moq : freightValue   // moq allocate; conservative
dutyPerUnit    = dutyMode==pct ? fobPerUnit * dutyValue/100 : dutyValue
landedPerUnit  = fobPerUnit + freightPerUnit + dutyPerUnit
```

Document on memo: freight totals allocated by **moq**.

```
contributionPerUnit = sellPricePerUnit - landedPerUnit
landedMarginPct = sellPricePerUnit==0 ? N/A : contributionPerUnit / sellPricePerUnit * 100
capitalRequired = landedPerUnit * max(moq, targetVolume)
breakEvenUnits = contributionPerUnit <= 0 ? Infinity : capitalRequired / contributionPerUnit
```

**Scenarios**
| Scenario | Rule |
|----------|------|
| Base | Primary quote + sellPrice + targetVolume |
| Downside | Landed = **max** across complete quotes (or primary×1.15 if only one); volume = 50% targetVolume; if demand `result == null` treat demand as **failed** for scenario narrative; if result set use 50% of result |
| Upside | Landed = **min** across complete quotes; volume = 150% targetVolume |

### System recommendation (non-binding)

```
if publish-invalid state → (don't show invest; force test_again checklist)
if any Untested load-bearing without plannedTest → test_again
else if base landedMarginPct < killMarginPct → kill
else if killDemandMetric non-empty:
     if demand missing or status != done → test_again
     else if result < killDemandThreshold → kill
     else → invest
else → invest   // no demand kill metric configured
```

UI: recommendation + checklist. **Founder sets `verdict` explicitly.** Memo disclaimer: "Not financial advice; founder judgment required."

### Edge-case matrix

| Case | Behavior |
|------|----------|
| Conflicting quotes | Base=primary; down/up use max/min landed |
| Partial quote | Excluded from math; draft save OK |
| In-progress demand | recommendation test_again |
| `result == null` in downside | demand treated as failed for scenario text |
| One currency only | enforce on case |
| Quote age >90d | warning badge |
| OCR | not in v1 |

### AI in v1 (Gate 2 only)

- Suggest missing tests / checklist copy.
- Help edit verdict note wording.
- **Never** write numeric ledger fields. No OCR. Existing canvas economics AI does not feed this Case.

### Dad Decision Memo contents

One printable page:
1. Title, date, currency, SKU
2. Verdict (founder) + system recommendation + disclaimer
3. Base unit econ table (landed, margin %, capital, break-even)
4. Scenario summary (base/down/up)
5. Knowns (Quoted/Measured rows with source refs)
6. Unknowns (Untested + planned tests)
7. Demand test card (0 or 1)
8. Kill criteria
9. `nextCheapestTest` (manual field; required on UI when verdict or recommendation is test_again)

### Gate 0 deliverable template (founder fills before Gate 1)

```
SKU:

Quote A: supplier / FOB / freight / duty / MOQ / file
Quote B: ...
Sell price hypothesis + how we'll test:

Decision moved? Y/N — notes:
```

### Acceptance tests (Gate 1 product)

- Draft save allows incomplete data.
- Publish blocked unless publish-tier validation passes.
- Memo printout contains sections 1–9.
- Fixture: 2 quotes + demand done below threshold + kill margin → recommendation `kill`; founder may set `test_again`.
- Gate 1 "dogfood ready" only after Gate 0 template fields are either present in UI or explicitly listed as Unknowns.
